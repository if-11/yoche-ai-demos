# 有车科技 AI 影视制作 SOP 网站设计规格

日期：2026-08-07  
状态：已完成设计确认，待用户复核后实施

## 1. 项目目标

将现有 AI 创作演示站升级为可持续维护的“AI 影视制作全流程 SOP”。主页负责展示前期、中期、后期的完整路径；每个专业主题进入独立子网页。网站不宣称已经完工，主页统一标记“持续梳理中”，后期专题统一标记“待完善”。

## 2. 已确认的设计原则

- 品牌视觉沿用有车科技现有黑、白、红体系和真实 Logo。
- 主页采用纵向制作时间线，不使用阶段切换隐藏内容。
- 首页直接展示真实专题名称和状态，不使用概念占位文案。
- 每个专题页为可独立分享的长页面。
- 新页面支持 Prompt 一键复制和 Skill 原始文件下载。
- 现有两个专题页保留正文与原交互，只在顶部增加“返回主页面”入口。
- 不增加上一步、下一步、相关专题或侧边目录。
- 案例图片使用用户提供的原始素材，不重新生成或替换。
- “画面去脏与干净重绘”与“图片 4K 修复”是两个独立专题。

## 3. 信息架构

### 3.1 主页

文件：`index.html`

首屏内容：

- 有车科技 Logo。
- 标题“AI 影视制作全流程 SOP”。
- 状态“持续梳理中”。
- 简短说明：网站用于沉淀从创意到交付的 AI 影视生产方法。

主体按照 01 前期创意、02 中期制作、03 后期制作纵向排列。每个阶段显示阶段目标、专题数量和专题卡片。专题卡片包含标题、用途摘要、状态和进入按钮。

### 3.2 前期创意

1. `ai-film-preproduction.html` - Brief 对齐与纸上剪辑
   - 使用现有网页。
   - 保留现有 Brief 确认清单、纸上剪辑模板与交互。
   - 顶部新增返回主页入口。

2. `creative-ideation.html` - 创意发想与参考检索
   - Brief 输入整理。
   - 创意方向发散与筛选。
   - 创意方案输出结构。
   - GPT 案例检索、新片场/场鸽参考检索方法。
   - 当前材料较少，页面标记“持续补充中”。

### 3.3 中期制作

3. `character-assets.html` - 人物资产
   - 人物三视图。
   - 电影感身份板。
   - 完整角色设定图。
   - 案例图片与可复制 Prompt。

4. `vehicle-assets.html` - 车辆资产
   - 单视角车辆资产。
   - 六视角车辆资产板。
   - 车型身份、结构和材质稳定性检查。
   - 案例图片与可复制 Prompt。

5. `scene-assets.html` - 场景资产
   - 室内/室外单场景主图。
   - 场景提示词公式。
   - 九宫格多视角一致性。
   - 摄影机、光线、材质和场景锁定规则。

6. `storyboard-image-prompts.html` - 分镜图片与提示词
   - 标准 Prompt 金字塔结构。
   - 图片反推 Prompt。
   - 多参考图组合与不可变条件。
   - 画面细节问题诊断。
   - 下载参考图控制 Skill。
   - 下载 Quill 提示词优化 Skill。

7. `image-cleanup.html` - 画面去脏与干净重绘
   - 脏点、脏线、扫描污渍、随机噪点的判断标准。
   - 转黑白线稿法。
   - 转中性白模法。
   - 结构参考图与风格参考图组合重绘。
   - NanoBanana 干净修复 Prompt。
   - 与 4K 修复的使用边界。

8. `ai-image-4k-restoration.html` - 图片 4K 修复
   - 使用现有网页。
   - 保留六种方法、快速诊断和现有交互。
   - 顶部新增返回主页入口。

9. `ai-video-generation.html` - AI 视频生成
   - 通用 Shot 表达。
   - 起始画面、主体动作、摄影机、环境、节奏与结束画面。
   - 稳定性限制和禁止项。
   - 视频抽图法。
   - 下载视频生成导演 Skill。

### 3.4 后期制作

以下页面都可以进入，但页面顶部必须显示“待完善 / 持续梳理中”。已知内容正常展示，新增内容只补充为可执行的框架，不伪装为最终定稿。

10. `post-material-management.html` - 素材筛选与管理
    - 素材收集、命名、筛选、版本与镜头状态框架。

11. `post-audio.html` - 音乐、音效与旁白配音
    - MiniMax、Suno 等现有工具入口。
    - 音乐、环境音、动作音效和旁白的分层框架。

12. `post-editing.html` - 剪辑节奏与叙事
    - 粗剪、精剪、节奏、转场和画面声音配合框架。

13. `post-finishing-delivery.html` - 精修与交付
    - Topaz/达芬奇超分。
    - 调色、字幕、混音、输出规格和归档框架。

## 4. 专题页结构

新建专题页按实际内容灵活组合以下模块，不强制每页完全同构：

1. 顶部返回主页入口。
2. 阶段标签、专题标题和状态。
3. 本步骤解决的问题与目标产出。
4. 操作流程。
5. 用户提供的案例图片。
6. Prompt 区块与一键复制按钮。
7. 检查清单或常见问题。
8. Skill 说明与下载按钮（仅在有对应 Skill 的页面出现）。

## 5. 交互与文件策略

- 站点保持纯静态 HTML/CSS/JavaScript，兼容 GitHub Pages。
- 新页面共享 `assets/site.css` 与 `assets/site.js`，避免重复维护样式和复制逻辑。
- 复制按钮从指定 Prompt 容器读取纯文本。成功后短暂显示“已复制”；失败时提示用户手动选择文本。
- Skill 文件放入 `downloads/skills/`，保留原始 Markdown 内容和可识别文件名。
- 用户原始案例图片复制到 `assets/images/` 下按专题分组，文件路径使用 URL 安全名称。
- 外部工具链接在新标签页打开，并带安全的 `rel` 属性。

## 6. 视觉方向

- 主页：深色首屏、红色强调、纵向阶段编号、浅色内容卡片区域。
- 专题页：与现有页面相同的高对比品牌语言，允许根据图片数量采用单列、双列或网格。
- 状态规范：
  - “可用”：正常强调色。
  - “持续补充中”：弱化但可点击。
  - “待完善”：灰色状态标签，但页面仍可进入。
- 响应式：桌面端保持清楚的阶段层级；手机端所有专题卡片自动变为单列，Prompt 和按钮不得产生横向滚动。

## 7. 内容边界

- 不擅自删除用户原始 Prompt、案例或工具名称。
- 对明显错字和排版符号可以做可读性修正，但不改变核心含义。
- 后期内容可以补充专业流程骨架，但必须与用户原始内容区分，并维持“待完善”状态。
- 不把画面去脏并入 4K 修复。
- 不为现有页面新增额外导航、相关推荐或阶段跳转。

## 8. 验证要求

### 内容与链接

- 首页 13 张专题卡片归类正确。
- 所有专题链接能打开，所有页面的返回主页入口有效。
- 后期 4 个页面均显示待完善状态。
- 外部链接、图片、Skill 下载无 404。

### 交互

- 每个 Prompt 复制按钮复制正确文本。
- 复制成功和失败状态均可理解。
- 下载按钮返回原始 `.md` 文件。
- 现有两页原交互继续工作。

### 视觉与兼容性

- 桌面与手机无横向溢出、重叠或被裁切文本。
- 图片保持正确比例并提供替代文本。
- 键盘可访问返回入口、复制按钮和下载链接。

### 回归保护

- 实施前记录现有两页正文区域的文件哈希或基线副本。
- 实施后确认除顶部返回入口及其必要样式外，没有改变原正文与交互逻辑。
- 发布后在 GitHub Pages 逐页验证主页、两个现有页面和全部新页面。

## 9. 发布范围

最终提交包含：更新后的主页、两个只增加返回入口的现有页面、11 个新专题页、共享样式/脚本、案例图片和 3 个 Skill 下载文件。发布目标保持现有 GitHub 仓库与 Pages 地址不变。
