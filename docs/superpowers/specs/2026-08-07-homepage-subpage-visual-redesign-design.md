# 有车科技 AI 影视 SOP 整站视觉重设计规范

日期：2026-08-07  
状态：设计方向已确认，待用户复核规范后实施  
选定方向：A「导演工作台」

## 1. 改造目标

解决当前主页与新增专题页视觉层级不足、排版松散、标题断行不稳定、返回入口位置不统一的问题。主页采用独立的「导演工作台」首屏；11 个新增专题页完整继承原有两个专题页的版式语言。原有两个专题页的正文内容与交互保持不变。

本次先完成本地版本，不推送 GitHub。待用户在本地确认后，再另行发布。

## 3. 主页首屏：A「导演工作台」

### 3.1 视觉结构

1. 顶部品牌栏：左侧有车科技 Logo，中间或右侧为“制作系统 / 前期 / 中期 / 后期”轻量导航，最右为“持续梳理中”状态。
2. 主视觉左栏：使用两行人工控制断行的品牌主张“把灵感，变成 / 可交付的影像。”，第二行用品牌红强调。
3. 主视觉右栏：半透明“从哪里开始？”工作台卡片，按 01 前期、02 中期、03 后期展示专题数量、状态与阶段入口。
4. 首屏底部：浅色快捷导航带，放置总览和高频专题入口。
5. 背景：沿用原有页面的深黑底、右侧红色径向渐变与大型圆环，不使用密集网格作为主装饰。

### 3.2 信息规则

- 首屏不把 13 个专题全部展开，避免视觉拥挤。
- 右侧阶段入口必须可点击，并滚动至主页对应阶段。
- 快捷导航只保留高频入口，不代替完整三阶段内容区。
- 首屏状态必须明确说明网站仍在持续梳理，不营造已经完工的印象。

### 3.3 首屏下方

- 继续按 01 前期创意、02 中期制作、03 后期制作纵向排列。
- 每个阶段先显示阶段标题、用途和专题数量，再显示专题卡片。
- 卡片缩短无效留白，标题与摘要形成稳定的上中下层级。
- 中期专题较多，使用两列或三列响应式网格；前期和后期保持视觉平衡，不强行拉满卡片高度。
- 后期使用弱化状态色，但仍保持可读、可点击。

## 4. 新增专题页统一模板

### 4.1 顶部返回区

- 页面最顶部设置独立黑色横条。
- “← 返回主页面”位于左上角，使用原有页面的圆角描边按钮。
- 返回区不放 Logo，不将返回入口移到右上角。

### 4.2 深色首屏

严格继承 `ai-film-preproduction.html` 的视觉语法：

1. 品牌行：左侧有车科技 Logo，右侧为“AI 影视新人训练 · 阶段 / 专题”胶囊标签。
2. 两栏布局：左侧为专题标题与说明，右侧为主题信息卡。
3. 标题：白色主句配红色强调句；每个专题人工设置桌面与移动端断行位置。
4. 信息卡：用 2 至 4 条专题问题、关键产出或检查重点替代当前单独的状态与说明。
5. 背景：黑色基底、右侧暗红渐变、大型半透明圆环和克制的玻璃卡片。
6. 首屏高度、左右宽度和留白密度向原有专题页看齐，避免当前页面过空。

### 4.3 页面内目录

- 深色首屏下方设置原有风格的白色胶囊目录栏。
- 目录仅链接本页章节，不增加“上一步”“下一步”或“相关专题”。
- 目录在滚动时保持可用，但不能遮挡章节标题。

### 4.4 正文内容区

- 内容最大宽度统一为约 1180px。
- 使用红色英文眉题、明确的大标题、灰色说明文字和白色圆角卡片。
- 问题、方法、检查清单优先使用双栏或三栏结构，减少无意义的大块空白。
- 图片按内容选择单张、双列或三列；保持原比例，避免为了填充而裁掉关键内容。
- Prompt 使用深色工具卡，保留一键复制与复制状态反馈。
- Skill 使用独立下载卡，保留原始 Markdown 下载行为。
- 后期页面在首屏和正文开头同时保留“待完善 / 持续梳理中”提示。

## 5. 标题与响应式规则

- 桌面端主标题不依赖浏览器随机换行，生成器为每页提供明确的标题行配置。
- 短标题可以单行；长标题最多两行，语义完整，不拆散固定词组。
- 正文大标题不出现单字孤行。
- 900px 以下将首屏变为单列，信息卡移到主标题下方。
- 640px 以下返回按钮、Logo、标题、胶囊目录和内容卡片分别缩放。
- 移动端目录允许横向滚动，但页面本身不得横向溢出。
- 图片、Prompt 和下载按钮在手机端改为单列。

## 6. 交互规则

- 所有页面返回入口均指向 `index.html`。
- 主页三个阶段入口使用页面锚点，不刷新页面。
- 页面内目录滚动到准确章节，并为固定目录预留偏移。
- 复制按钮继续读取对应 Prompt 的纯文本；成功显示“已复制”，失败提示手动复制。
- Skill 下载继续使用静态相对路径和 `download` 属性。
- 不增加轮播、自动动画、上一步、下一步或相关推荐。
- 动效只用于轻微悬停、按钮状态和滚动反馈，并遵守 `prefers-reduced-motion`。

## 7. 实现边界

- 共享视觉规则继续维护在 `assets/site.css`，复制交互继续维护在 `assets/site.js`。
- 页面生成逻辑继续由 `scripts/build-site-pages.mjs` 统一输出，避免手工维护 11 份重复结构。
- 为主页使用独立类名前缀，避免主页专属首屏影响专题页。
- 为新专题页使用统一模板类名前缀，避免覆盖原有两个专题页的内联样式。
- 不重新生成或替换用户提供的图片，不改写 Prompt 核心内容。

## 8. 验证标准

### 8.1 视觉

- 主页首屏与已确认的 A 方案在结构、比例、视觉重心和红黑品牌气质上保持一致。
- 11 个新增专题页的返回区、品牌行、双栏首屏、信息卡、圆环背景和胶囊目录与原有专题页明显属于同一套设计。
- 所有页面在 1440px、1024px、768px 和 390px 宽度下没有标题碰撞、意外孤行、横向溢出或内容遮挡。

### 8.2 内容与交互

- 13 个主页专题链接全部有效并归类正确。
- 11 个新增页面均可返回主页，页面内目录均可到达正确章节。
- 所有 Prompt 复制按钮有效，3 个 Skill 下载链接有效。
- 后期 4 个页面均明确标记未完成状态。
- 原有两个页面正文内容和既有交互未发生变化。

### 8.3 本地验收

- 先在当前本地服务器预览，不上传 GitHub。
- 完成自动链接与资源检查后，再用浏览器逐页检查主页、两个原页面、至少三个内容结构不同的新页面及全部移动端关键断点。
- 用户确认本地效果后，才进入 GitHub 发布步骤。

- 不把画面去脏合并进 4K 修复。

- 不新增上一步、下一步、相关专题、侧边目录或复杂动画。
- 不在本轮自动推送 GitHub。
